# Euler for iPhone

A SwiftUI client of the Connect API in `proto/euler/v1/`. It has chat, every
settings page the web has, and push for finished turns and tool approvals.
iPhone only, iOS 26 and later.

## Setup

You need a Mac with Xcode.

Set your Apple developer team and a bundle ID prefix you own in the
repository's `.env`:

```bash
EULER_IOS_TEAM_ID=ABCDE12345
EULER_IOS_BUNDLE_PREFIX=com.example
```

Then generate the project:

```bash
brew install xcodegen          # once
bun run ios:project            # after every pull: generates Euler.xcodeproj
open ios/Euler.xcodeproj
```

`Euler.xcodeproj` is generated from `project.yml` and never committed.
`project.yml` takes the team and the prefix from those two values.

One target builds two apps that install side by side. Each has its own server
address, user ID, and app group, and asks for the server address at
onboarding.

| Scheme | App | Bundle ID | Used with |
| --- | --- | --- | --- |
| `Euler` | Euler | `<prefix>.euler` | Production |
| `EulerDev` | Euler - Dev | `<prefix>.euler.dev` | The iOS test server |

`EulerDev` builds the `Dev` configuration with the blueprint icon `AppIconDev`.

## Layout

| Path | What lives there |
| --- | --- |
| `project.yml` | Targets, signing, capabilities (push, app group), packages, Info.plist keys. |
| `EulerAPI/` | Only the generated contract. `bun run proto` at the repo root rewrites `Sources/EulerAPI/Generated/`. |
| `Euler/App/` | Entry point, root view, `AppSession` (one per signed-in user), push. |
| `Euler/Core/` | Backend client and user header, identity and Keychain, the event stream and its reducer, Markdown and math, theme and fonts, image pipeline. |
| `Euler/Features/` | One folder per screen: Chats (home, drawer, new chat), Chat, Composer, Onboarding, Settings, Usage. |
| `Euler/Assets.xcassets/` | `Providers/` and `Thinking/` are generated by `bun run ios:icons`. Don't edit them by hand. |
| `EulerNotificationService/` | Attaches a reply's generated image to its notification. |
| `EulerTests/` | Swift Testing: the reducer, stream reconnects, streaming coalescing, Markdown and math, composer logic. |
| `EulerUITests/` | XCUITest flows against the scripted fixture backend. |

## Fonts and icons

The app bundles the web's fonts from `public/fonts/` unchanged and registers
them at launch, so both clients render the same faces. They are WOFF2, which
CoreText decompresses the first time it looks for a face in a file. Launch
looks up every file's faces off the main thread. Without that, the first chat
opened hangs.

`bun run ios:icons` writes the provider logos from `public/icons/` and the
thinking-level brains from `ui/components/ThinkingLevelBar.tsx` into the asset
catalog. It rewrites them for CoreSVG, which misreads compact arc flags and
gradients defined after use. Run it after changing either source.

Two things render differently from the web:

- The web's Default font, IBM Plex Sans, is bundled on neither client. On iOS
  it maps to the system font.
- An equation alone in its paragraph is a centered block on iOS. The web
  renders a single-line `$$…$$` inline.

## How it works

### Navigation

- The app opens on a new chat, as the web's home does.
- The chat list is a drawer from the leading edge, opened by the sidebar
  button or an edge drag. It has the web sidebar's New chat, ephemeral chat,
  Usage insights, Customization, and Settings.
- `openSettings` in the environment opens a Settings page. Inside Settings it
  pushes. Anywhere else it presents the sheet with that page at the bottom of
  the stack, so closing it returns to where it was opened from.
- A chat opened from the drawer swaps in under the drawer, which then slides
  away. Elsewhere the old screen fades out before the new one fades in
  (`HomeView.go`), because a transition on the stack's root view doesn't run.
- A chat that isn't loaded yet gets up to 300 ms to load first, so it arrives
  with its messages.

### Notices and forms

- `NoticeOverlay` shows `session.notices` in its own window above the app's,
  so a failure raised from a sheet shows over the sheet. A form says what a
  field is missing beside the field. A notice is for what only the server can
  tell.
- Hang a sheet opened from a form off one row, never off a `Section`. A
  section passes the modifier to every row, and the rows' sheets opening
  together close Settings under them.
- A sheet loads its own data. State the page reads only inside the sheet's
  closure is stale. The sheet gets it as it was when the page was first drawn.
- In `ThemedForm` and `ThemedList`, a tap outside a text field puts the
  keyboard away, since a multiline field has no key that does.
- A form's actions, such as Test and Save, sit under their section in
  `FormActions`, in the same place whether or not they can be used yet. A
  result shows in the section's own status row.
- Sheets close with the X of `CloseToolbarItem`.

### Theme and haptics

- `Palette` holds the web's tokens plus `tint`, each theme's signature hue,
  blue in Default. `tint` is for controls the pale accent would wash out:
  switches, checkmarks, unread dots, and the buttons that send or save. It is
  not for labels.
- `ThemedForm` and `ThemedList` give settings and sheets the theme's colors,
  with rows that act in the foreground color (`RowButtonStyle`).
- The mark on the new chat screen has its own color, `mark`. It is gold in
  Default because the blue was hard to see on the dark background.
- Choosing something ticks the same way everywhere (`Haptics.select`). Row and
  form button styles tick on their action, menu items through
  `Haptics.selecting`, and pickers through `Binding.ticking()`. Switches tick
  on their own.
- Firmer taps are kept for Stop and Delete. Success and failure use the
  system's.

### Chat

- **Sending.** A message sent to an idle agent shows in the transcript as soon
  as the server accepts it (`ChatStore.arriving`), in the row the saved message
  takes over.
- **Transcript rows.** The last row of the transcript's lazy stack is built
  whole. It holds the last few messages from when the chat opened, every
  message since, and the turn in progress. The lazy stack runs no transition
  for a row it builds, and it keeps stale heights for rows that change or
  move, so both have to happen inside one row.
- **Scrolling.** The transcript keeps its bottom edge in place as text arrives.
  A row opened by hand, such as a reply's thoughts, holds its own place and
  pushes what follows down (`resizeInPlace`).
- **Streaming.** `ChatStore` publishes each part of a chat separately, and
  `LiveReply` publishes token text at most once per display frame, so a long
  transcript doesn't redraw per token. Arriving reply text ticks the phone
  (`Haptics.streaming`), spaced out so fast text is a patter and not a buzz.
- **Message actions.** They are on a long press. Select text opens the message
  where any part of it can be copied.
- **Pasting images.** SwiftUI's text field pastes text only. `ImagePasteTarget`
  finds the UITextView behind the message box and gives that one view a
  run-time subclass. The subclass offers Paste when the clipboard holds an
  image and no text, and attaches the image.
- **Trace.** `TraceView` lists a reply's steps as cards. Each shows a tool
  call's arguments under their names and its result as code, held to a few
  lines. Longer text opens on a page of its own, where part of it can be
  selected.
- **Markdown.** swift-markdown (cmark-gfm) parses replies. Single newlines are
  line breaks, as with remark-breaks. `MathDelimiters` ports the web's math
  policy and SwiftMath typesets math. Formulas it can't typeset show as source.

### Server connection

- **Client.** `Backend` holds one Connect `ProtocolClient` with binary encoding
  at `<server>/api/rpc`. `UserHeaderInterceptor` sends `x-euler-user-id`.
- **Events.** `EventStream` keeps `EventService.Subscribe` open in the
  foreground and resumes after the last sequence it saw. `RuntimeState` is a
  port of the web's `applyEvent` in `ui/hooks/run/useAgentEvents.ts`. Keep the
  two in step. The stream closes in the background, which is how the server
  knows to push.
- **Identity.** The server address lives in defaults and the user ID in the
  Keychain. Onboarding takes a pasted ID, a scanned QR from the web's
  Settings > General > Show QR, or a new one. An address typed without a scheme
  is taken as `https`.
- **MCP sign-in.** Authorize opens the provider's page in a system sheet
  (`webAuthenticationSession`). The server finishes the sign-in on its own
  callback and redirects to `euler://mcp-oauth`, which closes the sheet.
  Requires Euler on HTTPS; see [OAuth](../docs/customization.md#oauth).

## Tests

Run these from the repository root.

```bash
(cd ios && xcodebuild test -project Euler.xcodeproj -scheme Euler \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -only-testing:EulerTests)
```

The UI tests need the fixture backend, which has no real model:

```bash
JOB_FIXTURE_PORT=5195 TOOL_PERMISSION_FIXTURE=1 bun tests/helpers/asyncFixture.ts &
(cd ios && xcodebuild test -project Euler.xcodeproj -scheme Euler \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -only-testing:EulerUITests)
```

`LiveServerTests` run against a real server when `EULER_LIVE_SERVER` and
`EULER_LIVE_USER` are set. Pass them to xcodebuild as
`TEST_RUNNER_EULER_LIVE_SERVER` and `TEST_RUNNER_EULER_LIVE_USER`.

Running on the iPhone, the iOS test server, and push are covered in
`.agents/skills/test-euler-ios/SKILL.md`.
