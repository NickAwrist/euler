Euler agent runtime: old vs new

The old runtime was a single browser request: the page sent the whole conversation, one agent ran, and the answer streamed back over that request. The new runtime lives on the server. Each chat has durable agents with their own inboxes. A scheduler decides what runs, and every change is broadcast to the browser as an event.

3A message's journey

What happens when you hit send. The HTTP request finishes at step 5; everything after that happens in the background and reaches the browser as events.

callpersistedevent to browserscheduling

If you send another message while this runs, steps 1–5 repeat and the message waits in the inbox. At step 10 of the next LLM call it gets delivered: the current reply is closed as its own segment, and the new message is added to the transcript before the model continues.

4Agent lifecycle

Every agent, main or sub, has one status column. idle means ready, not done: a subagent keeps its context until it's dismissed. The main agent never ends; Stop just sends it back to idle.

5Parent ↔ subagent: everything is a message

Agents never call each other directly; they send messages. enqueue() writes a message to the recipient's inbox. If the message wakes the recipient, the scheduler starts it. Reports arrive wrapped in <agent_message> envelopes, marked untrusted so they can't pose as the user.

6Limits and the automatic-turn budget

Agents can wake each other, so without limits two agents could loop forever and burn tokens. There are three guards.

3
active subagents per chat

Running or waiting subagents take a child slot. Extra subagents show as queued until a slot frees up. A waiting child keeps its slot, so a blocking spawn can't deadlock.

4
running activations per user

Across all chats, main agents included. Set with EULER_MAX_RUNNING_AGENTS. An agent waiting on a blocking spawn gives its slot back.

10
automatic turns per chat

Model calls triggered by agents or the runtime instead of by you. Tool continuations inside one activation don't count.

8Vocabulary

Activation: one run of one agent, from when it wakes until its loop ends. It's the unit the scheduler starts and Stop aborts.
Inbox: an agent's undelivered messages (agent_messages). The only way to give an agent input.
Wake: a message that makes the scheduler start an idle agent. Progress messages and control records don't wake anything.
Held: mail kept aside until you press Deliver: after a budget pause, a Stop, an error, or a restart.
Delivery: when an inbox message becomes model input. It happens right before each LLM call, not only at the start.
Segment: one stored assistant message. A reply that gets a delivery midway is split into segments around it.
Snapshot + events: the UI loads /runtime once, then applies sequenced events. resync means "reload the snapshot".
Checkpoint: which model-history length matched each transcript position, so rewind can cut both consistently.
